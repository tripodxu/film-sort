## 4. 可以优化的位置（按收益排序）

### 4.1 把「可量化事实」交给脚本，不再硬编码（最高收益）

新增 `scripts/docs-facts.mjs`，在 CI 的 `format:check` 之后跑：

- `git rev-list --count HEAD` vs 文档里的 commit 数；
- `git ls-files '*.ts' '*.tsx'`（排除 `*.test.*`）行数 vs 文档里的代码行数；
- `ls migrations | tail -1` vs 文档里的最新 migration；
- `worker/account.ts` 的 `PBKDF2_ITERATIONS` 必须等于 100_000；
- `src/` 内不得出现奖牌 emoji、`jellyBounce`（已有测试，但文档也应被同一事实源约束）；
- `src/lib/theme.ts` 的 `THEMES.length` vs 文档里的主题数。

任一不一致即失败。这样「文档漂移」从人工纪律变成门禁。

### 4.2 单一事实源（Single Source of Truth）

- **硬规则**现在有三份：`AGENTS.md` §4（8 条）、`MEMORY.md` §3（C1–C10）、`PITFALLS.md`。三份编号与粒度不同，任何一条变更都要改三处。
- 建议：`MEMORY.md` §3 作为唯一清单；`AGENTS.md` 只保留「必须遵守的 8 条摘要 + 链接」；`PITFALLS` 只讲事故，不复述规则。
- **migration / 路由 / 端点**同理：`docs/API.md` 与 `worker/index.ts` 的路由链应由脚本生成或校验，避免 73 条路由靠手抄。

### 4.3 去掉「约 1880 行起」这类行号

- 所有路由/行号引用改成符号名或命令，例如：
  - `grep -n 'url.pathname === "/api/health"' worker/index.ts`
  - `worker/index.ts` 的 `route()` 函数
- 行号只能作为「本次定位提示」，不能作为长期事实。

### 4.4 加 Markdown 结构与链接检查

- 重复编号（4.24/4.51）、表格列数、断链、重复标题锚点，都可以用零依赖脚本或 `markdownlint` 在 CI 拦住。
- 收益：这次审计里的 3.1、3.2 两类问题以后不会再出现。

### 4.5 让 `MEMORY.md` 的「活跃记录」自动退场

- 该区块从 2026-10-24 起就没有再更新，事实上已被 `TASK-LEDGER.md` 取代。
- 建议二选一：
  1. 删掉「活跃记录」，只保留身份、硬约束、稳定结构、待办焦点；
  2. 保留但加一条硬约束：「每次合并必须同步 MEMORY 顶部」，并纳入门禁。
- 当前状态是最差的：既保留，又过期。

### 4.6 `TIMELINE.md` 明确标注为「快照」

- 它自称覆盖到 2026-10-14，却仍在开头写「每日每条 commit 都可在本文找到」。
- 建议改成「截至 2026-10-14 的快照；之后看 `git log` / CHANGELOG」，或改为脚本生成。
- 当前 697 条 commit 中有 160+ 条不在时间线里。

### 4.7 归档/降级过期审查文档

- `docs/REVIEW-2026-10-27.md`、`docs/REVIEW-2026-10-29.md`、`docs/REFACTOR-UI-2026-10.md` 仍有「待办」语气。
- 建议在文首加状态横幅（「已完成 / 仅历史记录」），或移入 `docs/archive/`，避免被当成待办来源。

### 4.8 README 减重

- README 485 行，与 `FEATURES.md`、`API.md`、`USAGE.md` 大量重复；重复处最容易漂移。
- 建议 README 只保留：一句话、快速开始、文档导航、部署、安全摘要；功能细节全部指向 `FEATURES.md` / `USAGE.md`。
