## 二、P1：已修复（T-20261029-EXPIRY）

### 1. 所有「到期时间」实际被延长最多 24 小时 · 影响最大

- **根因**：写入用 JS ISO（`2026-11-27T20:00:00.000Z`），比较用 `datetime('now')`（`2026-11-27 20:00:00`）。
  SQLite 按字符串比，`'T'`(0x54) > 空格(0x20)，到期当天恒判「未过期」。
- **影响**：用户会话 30→31 天；管理员会话 7→8 天；**OAuth exchange 名义 5 分钟、实际最长约 24 小时**
  （该 code 会出现在 `/?oauth_code=` URL 中）；分享短链、验证码、扫码事务同理。
- **修复**：`account.ts` / `index.ts` / `verification.ts` / `qrTransactions.ts` 全部改为
  `julianday(expires_at) > julianday('now')`，写侧仍用 ISO，比较统一按时间点。
- **回归**：`worker/sessionExpiry.test.ts`（ISO 与 SQL 两种格式 + 禁用账号）、`verification.test.ts` ISO exchange 用例，
  全部跑真实 `node:sqlite`。

### 2. 管理员改密不吊销旧 token

- `handleAdminChangePassword` 只更新 hash，不删 `admin_sessions`；用户改密却会删 `user_sessions`。
- 影响：token 泄露后改密无法「踢下线」，旧 token 仍可用满 7 天。
- 修复：改密后清空 `admin_sessions`（含当前会话），后台提示重新登录并写审计（`index.ts:1618`）。

### 3. 重置密码验证码可重复使用

- `buildCodeGuardSql()` 只做 `EXISTS`，改密成功后不删验证码行；注册路径会删、重置路径不会。
- 影响：10 分钟有效期内同一验证码可多次改密，违背一次性消费设计。
- 修复：抽出 `resetPasswordWithCode`（`account.ts:181`），改密 UPDATE + 删验证码 + 吊销会话放进同一个
  D1 batch 事务；后两条以「新哈希」为守卫，错码时不误删验证码、不误踢用户下线。
- 回归：`worker/passwordReset.test.ts`（对码 / 错码 / 过期 / 重放）。

### 4. `/api/cache/clear` 匿名可调用

- 仅 `assertSameOrigin` + 5 次/10 分/IP；`assertSameOrigin` 对非浏览器客户端只是可伪造的头。
- 影响：任何人可周期性刷新缓存代次、清空全站海报/文字缓存，把压力打回上游。
- 修复：先限流后鉴权，要求登录（401 `authentication_required`，`index.ts:3104`）；
  前端 `SettingsMenu` 补 `Authorization` 头，未登录直接提示。

### 5. `/api/insights` 匿名消耗服务端 AI 额度

- 内置通道走 `env.AI_API_KEY`，仅 8 次/10 分/IP；同源头可伪造、分布式 IP 可放大。
- 修复：内置通道要求登录（401 `authentication_required`）；用户自带 `config` 仍可匿名使用（key 不落盘）。
  前端 `aiInsight.ts` / `AiInsightCard.tsx` 补对应错误码与文案。

### 6. 限流不准确 + 鉴权在限流之前

- `allowUpstreamRequest` 用 Edge Cache `match→put` 读改写（非原子）+ isolate 内存计数，并发/多机房会少计；
  缺 `cf-connecting-ip` 时全部落 `anonymous`。
- `/api/netease/*`、`/api/douban/*` 先 `getUserFromToken` 再限流，未登录请求可无限触发 D1 查询。
- 修复：两条路由改为先限流再查会话。
- **已知残余**：Edge Cache 读改写仍非原子，属平台约束；后续可用 Durable Object 或 D1 计数收敛。
