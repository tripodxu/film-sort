# 使用说明

## 从首页开始

ART/RANK 的主流程不要求登录。首页的“开始排序”会进入媒介选择；“比较画像”用于导入他人结果。登录入口只有在配置 Cloudflare Access 和 D1 后才会启用，游客画像仍可完整使用。

支持四个媒介：电影、书籍、音乐和其他。每个媒介可以单独完成一份榜单，完成后会并入同一个艺术人格画像。

## 选择作品

### 内置榜单

选择媒介后进入“内置榜单”，可以搜索榜单名称、说明或其中的作品。打开一份榜单后可取消候选作品，至少保留两件才能开始。

### 自定义 TXT / JSON

可以在“快速添加一件作品”中逐件回车加入，也可以一次粘贴一批。批量 TXT 可以一行一件，也可以使用逗号、顿号、分号或竖线分隔。最多导入 300 件作品，每件标题最多 160 个字符。登录后，载入的自定义清单会保存到“我的云端清单”。

```text
花样年华
重庆森林
春光乍泄
```

JSON 可以是字符串数组：

```json
["百年孤独", "活着", "1984"]
```

也可以补充创作者、年份和海报：

```json
[
  {"title": "Kind of Blue", "creator": "Miles Davis", "year": 1959},
  {"title": "Blue", "creator": "Joni Mitchell", "year": 1971, "posterUrls": ["https://example.com/cover.jpg"]}
]
```

海报 URL 必须是 HTTPS。画像导入会再次校验字段、排名连续性和大小，单个 JSON 最大 512 KB。

### 豆瓣 Top250

电影可以选择 Top 25、50、100 或 250。Worker 服务端读取豆瓣页面，避免浏览器跨域。二选一卡片的电影海报顺序是：豆瓣当前图片、豆瓣 Top250 索引及镜像 host、精确匹配的 IMDb suggestion 图片，最后显示无图占位。

豆瓣出现安全验证或网络错误时，页面会提示重试或回到内置榜单。此错误不会影响其他媒介和本地排序。

## 1v1 取舍

排序引擎使用可恢复的二分插入状态。相同作品组合会留出比较间隔，完成主排序后会进行少量稳定性复测。系统记录偏好证据并检查 A→B→C→A 这类回环：首次出现会自动安排复测，多次方向一致时会显示“偏好张力”提示，不会强行替用户改写结果。顶部状态栏显示已处理数量、比较次数和预计剩余。

| 操作 | 作用 |
| --- | --- |
| 点击左 / 右卡片 | 选择更偏好的一件 |
| `A`、`←`、`1` | 选择左卡片 |
| `D`、`→`、`2` | 选择右卡片 |
| 撤销 | 回到上一次选择前，包含展示顺序 |
| 略过 | 不把当前候选放入本次排名 |
| 暂放 | 暂时移到队列后面 |

快捷键在输入框获得焦点时不会触发。排序草稿保存在当前域名的 `localStorage`，刷新或重新打开首页后可选择“继续上次进度”。排序完成时草稿会清理。

## 艺术人格画像

排序完成后，当前媒介会自动保存。画像页可以：

- 切换电影、书籍、音乐和其他维度。
- 修改画像名称。
- 导出所有已经完成的维度。
- 添加新的媒介榜单，覆盖该媒介的旧版本。
- 复制压缩比较链接和二维码。

导出格式：

- `JSON`：推荐用于重新导入和比较，版本 2 包含 `rankings` 数组。
- `TXT`：适合纯文本阅读。
- `Markdown`：按媒介生成标题和编号列表。
- `CSV`：包含媒介、名次、作品、创作者和年份，并防止公式注入。
- `PNG`：支持编辑型总榜、海报拼贴和极简文字三种版式；海报失败时自动使用占位，不阻断导出。

## 比较他人结果

在“比较画像”中导入对方 JSON，或打开对方的比较链接：

1. 没有自己的画像时，页面会提示从对方的共同作品创建自己的排序。
2. 已有自己的画像时，只对相同媒介进行比较。
3. 结果显示作品重合度、加权偏好一致度、顺序一致率、Top 3 共识、名次距离、冠军一致和最大分歧。
4. 点击共同作品或分歧作品可按需读取豆瓣详情；音乐详情中可以主动请求一次试听片段。

比较会按标题、年份和创作者做规范化匹配，不会把电影和书籍中的同名作品混为一谈。重合度使用并集计算；只有一个共同作品时顺序一致率显示 `--`。

## 游客与账号

游客模式的数据不离开浏览器，适合快速体验。启用账号同步后，登录按钮会进入账号流程；画像变化会自动防抖保存，切到后台、网络恢复或关闭页面时会再尝试同步。同步失败不会覆盖本地画像。登录用户还可以管理自己的云端清单。管理员可在 `/admin` 查看账户状态、禁用/恢复账户、清理画像和云端清单，并查看海报错误聚合。

## 常见问题

### 海报为什么是占位？

远程图片可能被上游限流、失效或不是允许的图片 host。Worker 会尝试豆瓣镜像和 IMDb 备用；所有来源失败时仍可正常排序。

### 为什么豆瓣接口返回不可用？

豆瓣页面可能要求验证或限制当前出口。稍后重试，或使用内置榜单 / 自定义清单。部署到 Cloudflare 后，Worker 的出口与本地不同，成功率可能不同。

### 为什么比较链接很长？

未配置 D1 时，画像会压缩到 URL 的 hash 中。作品和维度越多，链接越长；超过浏览器可用长度时请改用 JSON 文件。

### 刷新后没有草稿？

草稿只存在当前浏览器和域名。隐私模式、清理站点数据、换域名或排序已经完成，都会导致找不到草稿。
