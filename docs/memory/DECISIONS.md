## D-20260928-05 · Jev 代判阈值定 0.8，且默认关闭

**背景**：Jev 辅助模式要在排序中替用户做判断，但用户选择是本产品的核心资产。
**决策**：置信度 ≥0.8 才自动落位并显式标注「AI 代判 · 置信 NN%」且可撤销；低于阈值或处于复测阶段一律交还用户；功能开关默认**关**。
**理由**：① 错了要能被发现和纠正，静默代判会污染画像；② 复测阶段的数据用于校准，不能被模型自我强化；③ 默认关 = 新用户不受影响，符合「主链路永不依赖 AI」原则。
**代价**： adoption 依赖用户主动开启。
**相关**：`src/lib/useSorting.ts`、`/api/ai/jev-pick`、ROADMAP 1.5。

## D-20260928-04 · 键控竞态守卫：迟到响应一律丢弃

**背景**：Jev 代判是异步的，用户在等待期间可能已经手动选了。
**决策**：每对取舍持有一个键，响应回来时若键已变更（用户已做出真实选择）则丢弃响应，绝不覆盖。
**理由**：真实用户选择优先级高于任何预测。这条规则适用于**所有**异步写状态的场景（云同步水合门也用了同款代际守卫）。
**相关**：与 D-20260925-03 同类。

## D-20260928-03 · 首屏优化走「路由拆包」而非「依赖裁剪」

**背景**：index chunk 1072 KB。先做了事实核查：qrcode 已是动态引入，主包体积来自五个千行视图全量打包。
**决策**：对 `SourceView` / `ProfileView` / `CompareView` / `ShareView` / `PlazaPostView` 改 `React.lazy` + Suspense，沿用 `DeferredOrb` 同款模式。
**结果**：1072→964 KB（gzip 307→279）。
**教训**：**优化前先做事实核查**，直觉（"qrcode 太重"）常常是错的。

## D-20260928-02 · OG 元数据必须服务端注入，且失败必须静默降级

**背景**：爬虫不发 JS，SPA 的 `/share/:code`、`/plaza/:id` 分享出去是空白卡片。
**决策**：worker 拦截这两个 HTML 路由 → 从 D1 取标题/作者/首图 → 往 `env.ASSETS` 的 index.html `<head>` 注入 meta 再返回；`cache-control: public, max-age=300`；爬虫与用户同 URL，不做 UA 分支。
**约束**：用户可控文本**全部先 HTML 转义**再进 meta；任何 DB/解析异常降级为「无 OG 的普通 SPA」，绝不让异常变成 500。
**理由**：分享链路是增长漏斗，但绝不能为了 OG 让主页面挂掉。

## D-20260928-01 · Jev 集成四原则（适用于所有 AI 接入）

1. **key 不内置** —— 用户自填存浏览器 localStorage，请求透传给 worker，worker 不落盘任何 key（与 AI 点评一致）。
2. **决策而非生成** —— 只把「本质是判断」的环节交给 Jev（消歧、护栏、预测预填、代判）；文本生成类继续走 OpenAI 兼容通道。
3. **降级可用** —— 每个接入点必须在未配 key / 请求失败时回落到现有逻辑或明确提示，主链路永不依赖。
4. **非关键路径先行** —— 早期访问的新服务先接非关键链路。

## D-20260925-04 · 出站请求统一收口到 `worker/outbound.ts`

**背景**：多处 fetch 直连外部域，存在 SSRF 面。
**决策**：新增 `fetchBounded` 统一策略 —— 精确 host 白名单、`redirect: 'manual'` 逐跳复核、响应字节上限。所有对外 fetch 必须走它。
**理由**：散落的白名单判定无法审计；唯一收口处才能让安全契约可测试（`outbound.test.ts` 覆盖重定向预算）。
**相关**：与 C3 图片白名单同理 —— **安全判定必须有唯一入口**。

## D-20260925-03 · 云同步「水合门 + 会话代际」

**背景**：并发的云同步响应会互相覆盖（旧响应后到覆盖新状态）。
**决策**：引入水合门（hydration gate）与会话代际号，旧代际响应直接丢弃。
**理由**：与 D-20260928-04 是同一类问题的两种形态：**异步写状态必须有代际/键控守卫**。

## D-20260925-02 · 主题与光球特效做成插拔注册表

**决策**：`src/lib/themeRegistry.ts` + `src/lib/orbEffects/` 注册表，配套 `docs/THEME-PACKS.md` / `docs/ORB-EFFECTS.md` 规范，支持用户导入主题包（重建式安全注入）。
**理由**：避免每加一个主题就改一遍核心；把扩展点做成**数据与文档契约**，而不是代码分支。
**代价**：导入主题包是重建式注入，会短暂重建样式（已接受）。

## D-20260925-01 · PBKDF2 迭代数上限压到 100,000

**背景**：600k 迭代在 Cloudflare 上让注册 / 改密 / 重置**全线崩溃**。
**根因**：workerd（包括开了 `nodejs_compat` 的 `node:crypto`）拒绝 >100k 迭代。
**决策**：硬上限 100k；哈希格式 `pbkdf2$<iterations>$<salt>$<hash>` 自带 iterations，将来平台放开可平滑上调。
**教训**：**平台能力必须在目标运行时上实测，不能按 Node.js 的假设写代码**。这是本项目最重要的一条环境教训。

## D-20260922-06 · 视觉回归用「270 张截图 × 2 轮零差异」

**决策**：建立 `scripts/ui-shot.mjs` + `ui-diff.mjs`（零依赖 PNG 比对）+ 截图基线，重大视觉改动前后各跑一轮，要求零差异（容忍度经构造边界 + 位移签名核定，而非只看百分比）。
**理由**：纯百分比差异具有误导性（一次 bento grid 的 mode delta 只有 0.0014%，实际是 `display:block` 空化了 `grid-template-columns`）。
**教训**：**判定标准必须能区分"真的没变"和"差异小到看不见"**；且**构建期间禁止截图**（dist 重建会让 ENOENT 杀死整轮）。

**理由**：把视觉风险与功能风险解耦，出问题时回滚面清晰。

## D-20260922-03 · `--text-3` 对比度 74% → 78%

**理由**：classic / surface3 组合下 4.11:1 不达 WCAG AA；78% 后为 4.62:1，对 44×11px / 44×12px 元信息达标。
**方法**：`scripts/ui-contrast.mjs` 扫描 + `docs/ui-contrast.json` 存档，**对比度用工具判不用肉眼判**。

## D-20260922-02 · 布局模式与主题正交（`data-layout` vs `data-theme`）

**决策**：`src/lib/layout.ts` 克隆 `theme.ts` 的实现，两者互不耦合。
**理由**：主题管「长什么样」，布局管「怎么排」，交叉组合会导致组合爆炸。

## D-20260922-01 · Token 体系分 L1/L2 两层 + 散落 hex 归零

**决策**：`styles.css` 全面令牌化（545 个 var / 194 处 color-mix）；色板类的逐字色值提升为 token，逐字值目标是 zero-diff。
**理由**：主题系统要求所有颜色可替换，任何硬编码 hex 都是主题切换的漏点。

## D-20260917-03 · 读侧永不删数据

**背景**：画像读写两侧校验口径不一致，导致「保存后刷新整份消失」。
**决策**：口径收敛到一处，**读取侧永远不因为校验失败而删除数据**，只在写侧做规范。
**理由**：读侧删数据 = 静默数据丢失，是最难排查也最难挽回的一类 bug。

## D-20260917-02 · 海报 URL 绝不进 `items`，落库白名单唯一出口

**背景**：150 首歌的画像因 posterUrls 数组超过 D1 的 512KB 限制，导致云端读取与广场发布双双失败（三连修 `51dfc8d` / `58da68a` / `4ce1f15`）。
**决策**：海报走独立的 `poster_urls` 侧表（migration 0022）；`shared/storedItem.ts` 是「什么能落库」的唯一判定出口。
**理由**：分散的字段白名单无法保证体积约束；唯一出口才能顺带做体积治理。

## D-20260917-01 · 豆瓣图片一律走代理

**背景**：豆瓣海报直连必然 418（反爬）。
**决策**：豆瓣系图片全走自建图片代理，并让图片请求免于抓取节流。
**理由**：反爬策略会持续变化，**把易变的上游细节收敛到代理层**。

## D-20260916-02 · 音乐试听走 Deno Deploy 代理

**背景**：CF Worker 出口、gdstudio、网易云出口全部被封禁。
**决策**：音乐试听链路迁到 Deno Deploy（GCP 出口可达）。同时把域名补进 CSP `connect-src`。
**教训**：**CSP 拦截在浏览器里是静默的** —— 表现为"功能全部降级到失败的 Worker 端点"，极易误判为上游挂了。改外部域必须同步 CSP。

## D-20260912-03 · 会话 token 不再出现在 URL

**决策**：OAuth 成功后用一次性 code（5 分钟有效、用后即焚，存 `oauth_exchanges` 表）交换会话 token，30 天 token 不进重定向 URL 与浏览器历史；OAuth 回调强制校验 HttpOnly Cookie 里的 state。
**理由**：URL 里的 token 会被 Referer、日志、浏览器历史泄露。

## D-20260912-02 · 密码哈希升级 PBKDF2-SHA256 加盐

**决策**：`pbkdf2$<iterations>$<salt>$<hash>`，恒定时间比较；旧的 10 万次或无盐 SHA-256 在**登录成功时透明升级**。
**理由**：不能强制所有用户重置密码，透明升级是唯一平滑路径。（迭代数后来因 D-20260925-01 下调。）

## D-20260912-01 · 广场列表走瘦身响应 + 服务端排序

**决策**：列表接口只返回前三名作品与批注数量（`json_extract`），排序/搜索/筛选全在 SQL 侧；前端无限滚动。
**理由**：广场帖子量会持续增长，全量传输不可持续。

## D-20260909-02 · 分享链接从内联 base64 改为短码

**决策**：`POST /api/share` 生成 8–12 位短码存 `shared_links`，`/share/<code>` 与 `/encounter?payload=<code>` 两种入口。
**理由**：base64 payload 过长且不可撤销、不可设有效期。

## D-20260909-01 · 两套链接语义分离

| 链接 | 格式 | 行为 |
|------|------|------|
| 比较链接 | `/encounter?payload=<短码>` | 对方打开直接进比较界面 |
| 分享链接 | `/share/<短码>` | 对方打开进查看页面 |

**理由**：传播场景与比较场景是两件事，混在一起会让 recipient 困惑。

## D-20260908-01 · 详情简介「豆瓣官方优先，维基兜底」

**决策**：简介优先取豆瓣官方详情页（`v:summary`，零歧义），失败降级维基消歧打分（限定标题 / 类型声明 / 年份守卫），再百度百科兜底。

**代价**：维基消歧打分逻辑复杂，是后续 Jev Phase 2 想替换掉的目标。
