## 3. 已确认并修复的问题

### F-01 · P2 · 风控是终态，但轮询没有停止

- **原位置**：`usePlatformConnect` 的扫码轮询 effect。
- **原逻辑**：只排除 `confirmed` 和 `expired`，没有排除 `risk`。
- **影响**：连续 3 次风控后虽然展示 Cookie 降级入口，`setInterval` 仍每 2.5–3 秒请求一次。既消耗 `netease/douban` 配额，也可能继续触发上游风控。
- **修复**：新增 `shouldPollQrState()`，仅 `waiting / scanned` 且弹窗打开、已有二维码时允许轮询；`confirmed / expired / risk` 都作为当前二维码终态。
- **测试**：终态参数化测试，特别锁定 `risk === false`。

### F-02 · P1 · 慢响应造成同一二维码并发轮询

- **原位置**：`setInterval(() => void poll(), …)`。
- **原逻辑**：定时器不等待上一个异步 `poll()`；请求也没有超时。
- **影响**：上游响应超过轮询间隔时，同一二维码会同时存在多个轮询。确认阶段可能重复调用上游、重复消费事务 / 写凭证，并重复触发 `onConnected`。
- **修复**：增加 `inFlight` 排他，上一轮未完成就跳过本轮；每轮增加 15 秒超时；`finally` 必须复位；JSON 解析后再次检查 `stopped`，防止关闭后的迟到响应更新状态。
- **测试**：源码生命周期绊线锁定排他、超时与 `finally` 复位。

### F-03 · P1 · 断开失败仍宣称“加密 Cookie 已删除”

- **原位置**：`disconnect()`。
- **原逻辑**：只捕获网络异常；无论 HTTP 401 / 429 / 500 / 503，随后都会清除本地连接态并显示删除成功。
- **影响**：UI 与服务端真实状态分裂。用户以为凭证已删除，实际 D1 保险库可能仍保留，属于明确的错误安全承诺。
- **修复**：抽出 `requestPlatformDisconnect()`，只有 2xx 返回成功，并加 15 秒超时；失败时提前返回，保留连接态，提示“连接尚未变更”。
- **测试**：204 成功；401 / 429 / 500 / 503 全部失败；网络异常失败；失败分支必须先于 `setConnected(false)` 返回。

### F-04 · P2 · 发码响应乱序可覆盖新二维码

- **原位置**：`issueQr()` / `closeQr()`。
- **原逻辑**：发码包含 fetch、动态导入与二维码 Data URL 生成，但没有代际判断。
- **影响**：连续换码时较慢的旧响应可能后落地，覆盖新二维码；关闭弹窗后旧响应也会继续写状态。网易云链路比豆瓣多两个异步边界，风险更明显。
- **修复**：每次发码递增 `issueGenRef`；响应后和二维码生成后都核对代际；关闭弹窗使旧代际立即失效；旧代际失败也不能把新一轮误标为过期；发码增加 20 秒超时。
- **测试**：代际递增、双重响应核对、关闭失效与失败分支均有绊线。

### F-05 · P2 · “归零自动换码”只有文案，没有行为

- **原位置**：倒计时 effect 与 `autoRefreshQr()` 调用关系。
- **证据**：倒计时归零只执行 `setQrState("expired")`；`autoRefreshQr()` 唯一调用方是弹窗“重新生成”按钮。README、USAGE 与按钮提示却都写着自动换码。
- **影响**：用户等待自动恢复时实际停在过期态；扫码链路需要额外手动操作。
- **修复**：进入 `expired` 后自动调用 `autoRefreshQr()`，继续使用最多 2 次的现有限制；`risk` 不进入该分支，避免与 F-01 相互抵消。
- **测试**：锁定 expired 自动触发、次数上限，以及 risk 不自动重试。

## 5. 未修问题与后续建议

### R-01 · P2 · `checkStatus()` 仍缺少超时与latest-only守卫

- 当前状态查询没有 `AbortSignal.timeout`，也没有类似发码的代际判断。
- 账户 / 平台快速切换时，旧响应理论上可覆盖新状态；黑洞网络下请求会等到平台默认超时。
- **建议**：下一批为 `checkStatus` 增加 15 秒超时、状态代际和 HTTP `response.ok` 分支，并补 Hook 级浏览器测试。本轮没有把未验证的额外重构混入已完成的 5 项修复。

### R-02 · P1（存量安全债）· 会话 token 明文入库

- `user_sessions` / 管理会话仍按 token 原值查询与存储；数据库泄露时可直接重放未过期会话。
- 这不是本轮新引入问题，既有审计已登记。
- **建议**：独立安全批次实施“只存 SHA-256 散列 + 登录时兼容迁移旧行 + 全鉴权路径切换 + 过期清理”，需要 migration、线上数据兼容和吊销回归，不适合与本次局部修复混改。

### R-03 · P3 · `wrapped.ts` 的动态拆包没有按意图独立成块

- 构建提示：`App.tsx` 动态导入 `wrapped.ts`，但 `exportPng.ts` 又静态导入它，因此动态导入不会把模块移到另一 chunk。
- 当前不造成功能错误，但会让拆包意图与实际产物不一致。
- **建议**：让年鉴导出只通过一个动态入口加载并显式 re-export 所需函数，或取消无效动态导入；前后比较 manifest 与首屏闭包守卫，不要直接改成 `App.tsx` 静态导入。

### R-04 · P3（观察项）· Three.js 懒块 530.82 kB

- 该块超过 Vite 500 kB 提示线，但 gzip 为 133.08 kB，且 `OrbScene` 不在首屏关键路径。
- **判断**：当前属于可接受的懒加载成本，不应为消除警告而盲目拆 Three.js 或提高 warning limit。若真实性能数据指向光球加载，再单独做按需特效拆分。

### R-05 · P1（验证缺口）· 真实账号与线上行为尚未验证

- Node 单测不能证明真实豆瓣 / 网易云风控、扫码确认和 D1 删除行为。
- 项目台账中近期若干任务也仍标记“本地全绿、待线上验证”，存在把本地结果误当交付完成的流程风险。
- **建议**：部署后按 §7 走查，再把台账状态改为完成；未走查前保持 🔄。

## 7. 部署后的最小验收清单

1. **风控停止**：连续返回 3 次 risk 后展示 Cookie 降级卡；继续观察至少 10 秒，不再新增 `/qr/poll` 请求。
2. **慢请求排他**：把 poll 延迟到 5 秒，确认任意时刻同一二维码最多一个未完成请求；恢复后立即能继续轮询。
3. **自动换码**：让倒计时归零，自动发新码且刷新计数加 1；第二次过期再换一次；第三次不再自动请求并显示上限提示。
4. **乱序发码**：第一次发码延迟、第二次先发回，最终只能显示第二次二维码；关闭弹窗后第一次响应不得重新写入。
5. **断开失败**：模拟 500 / 401，连接态保留并显示“尚未变更”；随后模拟 2xx，才显示断开并确认保险库记录已删除。
6. **主链路回归**：真实账号分别完成一次网易云、豆瓣扫码连接与清单导入，确认没有重复 `onConnected`、重复歌单加载或旧二维码串号。
