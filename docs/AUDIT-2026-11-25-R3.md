## 3. 已确认并修复的问题

### A-01 · P2（新发现）· 六个写请求无超时，黑洞网络把全局 busy 永久锁死

- **位置**：`src/App.tsx` 的 `syncPlazaPost` / `shareSingleRanking` / `publishToPlaza` / `publishProfileToPlaza` / `share` / `generateShareLink`。
- **根因**：六处 `fetch` 都没有 `AbortSignal.timeout`，且每处都 `setBusy(true)` → `finally setBusy(false)`。这个 `busy` 是**全站共享**的（分享画像、导出 PNG、年度年鉴、发布按钮都 `disabled={busy}`）。连接挂起不拒绝时（黑洞网络 / 代理吞包），`finally` 永远不执行，所有 busy 门控按钮一起锁死，只能刷新页面。
- **与 N-05 同族**：上轮只修了被点名的 Cookie 提交那一个，同族的六个漏网——教训已沉淀 `PITFALLS.md` 4.73。
- **修复**：六处统一加 `AbortSignal.timeout(20000)`（与 Cookie 提交 / 详情链路口径一致）；六个入口同时加 `if (busy) return` 防重入。
- **测试**：绊线按族写——遍历六个函数块断言超时与入口守卫（`ui-fixes.test.ts`）。

### A-02 · P3（上轮 R-04 + 新发现）· busy 释放不受代际守卫保护，比较按钮可并发

- **位置**：`src/App.tsx` 的 `share()` / `generateShareLink()`；`src/views/ProfileView.tsx` 比较按钮。
- **根因**（两层）：
  1. 上轮加的代际守卫只拦「状态写入」，`finally { setBusy(false) }` 无条件执行——`try` 里 `return` 不跳过 `finally`，迟到的旧请求会把新请求刚置上的 busy 解开；
  2. 「复制比较链接」按钮没有 `disabled={busy}`（上轮 R-04 原文），两类链接请求可并发。
- **修复**：两处 `finally` 改为 `if (generation === shareGenRef.current) setBusy(false)`；比较按钮加 `disabled={busy}`；入口防重入（A-01 已含）。既有 `shareLink.test.ts` 绊线**零改写**（仅更新一条过时注释，断言未动）。教训沉淀 4.74。
- **残留**：`setQrUrl(await makeQr(...))` 的 await 窗口理论上仍可被新一代覆盖——入口守卫 + disabled 后 UI 不可达，且修复需改写上轮绊线（按约定须先确认），登记不做（§5）。

### A-03 · P3（上轮 R-01）· 发码非 2xx 被当成「二维码过期」并自动换码

- **位置**：`src/lib/usePlatformConnect.ts` 的 `issueQr()`；`src/components/QrConnectModal.tsx`。
- **根因**：401 / 429 / 5xx 同样走 `response.json()` → 缺 `unikey/code` 抛错 → `expired` → 自动换码分支再打最多两次限流端点，最后显示「刷新次数已达上限」，真实原因（登录失效 / 被限流）被掩盖。
- **修复**：
  - `QrState` 新增独立终态 `"failed"`：非 2xx 在解析二维码字段**之前**分流，带代际守卫；不轮询（`shouldPollQrState` 白名单不含）、不进自动换码（effect 仍只认 `expired`）；
  - 新纯函数 `qrIssueFailureMessage(status, body, t)`：401/403 → 登录失效文案，429 → 限流文案 + Cookie 降级指引，其余优先透传服务端 `msg/error`，缺失时兜底带状态码；
  - 弹窗复用过期遮罩渲染「重试」按钮（手动重试走既有 `autoRefreshQr` 预算，防轰上游）；
  - 网络错误 / 超时 / 畸形 2xx 仍走 `expired` + 有限自动换码（瞬时故障的合理恢复路径），**既有 catch 绊线原样保留**。
- **测试**：8 项（文案矩阵 6 + 终态/接线绊线 2）。

### A-04 · P3（新发现）· 单榜比较链接兜底改写失败时，把分享页 URL 当比较链接复制

- **位置**：`src/App.tsx` 的 `shareSingleRanking`。
- **根因**：`compareUrl` 缺失时用正则把 `/share/<code>` 改写成 `/encounter?payload=<code>`；正则不匹配时 `replace` 原样返回分享 URL，随后以「比较链接已复制」提示复制出去——对方打开的是只读分享页而不是 PK 页（N-02 同族的静默错配）。当前 Worker 恒返回 `compareUrl`，此路径是对旧后端的兜底，但兜底本身必须失败得诚实。
- **修复**：抽纯函数 `compareLinkOf(data)`（`src/lib/shareLink.ts`）：改写不生效返回 `undefined` 走失败分支。
- **测试**：4 项（优先级 / 改写 / 三种不匹配形状 / App 接线）。

### A-05 · P3（上轮 R-02，可访问性）· 略过/暂放后键盘焦点掉回 body

- **位置**：`src/views/SortingView.tsx`。
- **根因**：`275cbf2` 在两个按钮 `onClick` 里 `blur()`，键盘用户 Enter 触发后焦点掉回 `body`，每次操作都要从头 Tab。
- **修复**：对决区容器 `.duel-grid` 加 `ref` + `tabIndex={-1}` 作稳定锚点；`blur()` + `act()` 后 `requestAnimationFrame` 把焦点移到锚点（`preventScroll`），下一次 Tab 直达第一张卡片。排序完成视图卸载时锚点为空操作，焦点由既有 `useRouter` 的 `main.focus()` 接管。焦点环走全局 `:focus-visible`（仅键盘触发），**零 CSS 改动**。
- **测试**：绊线断言锚点存在、两处 blur 都跟着锚点接管。

### A-06 · P3（11-24 R-03）· wrapped 双入口使动态拆包意图落空

- **位置**：`src/App.tsx` `exportWrapped`；`src/lib/exportPng.ts`。
- **根因**：App 动态导入 `wrapped.ts`，但 `exportPng.ts` 静态导入它——Rollup 警告「dynamic import will not move module into another chunk」，拆包意图与产物不一致。
- **修复**：`exportPng.ts` re-export `readDraftLike` / `draftInsight`，App 只保留 `import("./lib/exportPng")` 一个动态入口。
- **实测**：构建警告消除；manifest 中 wrapped 并入 `exportPng` 懒块（`15.38 → 16.53 kB`，gzip `6.07 → 6.53 kB`），**首屏入口闭包不含 wrapped**（manifest 闭包遍历验证）；主入口 `217.90 → 217.36 kB`（gzip `77.57 → 77.31 kB`）。

## 8. 部署后的最小验收清单

**当前进度**：部署与 §6.1 机器验证已完成；下列 1–7 依赖请求挂起模拟 / 429 拦截 / 键盘操作 / 真实出图，需人工浏览器走查；第 8 条与 AUDIT-2 §8 合并执行。

1. **写请求超时**：拦截 `/api/share` 挂起不响应，点「复制分享链接」→ 20 秒内按钮恢复可用并提示失败；期间「分享画像 / 导出」按钮不得永久锁死。
2. **发码 429**：拦截 `/api/douban/qr/issue` 返回 429 → 弹窗显示「请求过于频繁…」+「重试」按钮；Network 面板确认**没有**后续自动发码请求。
3. **发码 401**：同上返回 401 → 显示「登录已失效，请重新登录后再试。」。
4. **键盘焦点**：Tab 到「略过」按钮按 Enter → 焦点落在对决区（键盘焦点环），下一次 Tab 直达第一张卡片，不必从头 Tab。
5. **比较按钮 disabled**：任一链接生成中，「复制比较链接」按钮置灰。
6. **年度年鉴**：画像页导出「年度年鉴 PNG」正常出图（wrapped re-export 链路）。
7. **单榜分享**：榜单菜单内分享，复制结果为 `/encounter?payload=…` 形状。
8. 合并执行 AUDIT-2 §8 的七条（主题模板 / 分享输出区 / 状态容错 / 登出清理 / 扫码自动关闭 / Cookie 超时 / 真实账号主链路）。
